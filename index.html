DevOps Learning Path

Git & GitHub

Why learn it? Git and GitHub form the foundation of modern software collaboration and DevOps automation. Version control enables teams to track changes, work across isolated branches, review code, and trigger CI/CD pipelines automatically on push or pull requests.

Key Topics:

  • Version control fundamentals and repository lifecycle
  • Git CLI essentials: init, clone, add, commit, push, pull, status, diff
  • Branching, merging, resolving merge conflicts, and git rebase
  • GitHub Pull Requests, code reviews, and protected branches
  • SSH key authentication, .gitignore configuration, and repository secrets
  • Trunk-based development vs. GitFlow workflows

Docker

Resource: https://youtu.be/OhnTMWmfTBE?si=AFosIZ1MAWEPtlZA

Why learn it? Docker packages an application together with its runtime dependencies so it can run consistently across development, testing, and production environments.

Key Topics:

  • Images vs. containers
  • Dockerfile writing and common instructions
  • Volumes and bind mounts
  • Networking: bridge, host, and overlay
  • Docker Compose for multi-container applications
  • Image optimization and multi-stage builds
  • Container environment variables and secrets
  • Health checks and restart policies

Kubernetes

Resource: https://youtu.be/rBeyHDKLVqM?si=Tl3-pCYTzgMOPef_

Why learn it? Kubernetes orchestrates containers, providing scheduling, service discovery, scaling, rolling deployments, and self-healing for production workloads.

Key Topics:

  • Pods, Deployments, and Services
  • ConfigMaps and Secrets
  • Persistent Volumes (PV) and Persistent Volume Claims (PVC)
  • Ingress and Nginx Ingress
  • Rolling updates and rollbacks
  • Resource requests and limits
  • Liveness and readiness probes
  • Namespaces and basic RBAC

CI/CD Pipelines

Resource: https://youtu.be/y7S2oSjJ8PA?si=t8hGHupydaml9YQ-

Why learn it? CI/CD automates the path from source code to a tested and deployable artifact, reducing manual deployment work and improving release consistency.

Key Topics:

  • GitHub Actions workflows
  • Docker image building and publishing automation
  • Automated unit/integration testing
  • Deployment strategies: blue-green and canary
  • Secrets management in pipelines
  • Environment separation: development, staging, and production
  • Rollback and deployment failure handling

AWS (topics)

Resource: https://youtu.be/N4sJj-SxX00?si=wprIVRlQ5bRCfYGx

Focus first on the core AWS services below. Understand how they connect to form a production deployment architecture rather than studying each service in isolation.

3.1 AWS IAM — Identity and Access Management
Purpose: Controls who or what can access AWS resources. It is the foundation of cloud security.

  • Users, Groups, Roles, and Policies
  • IAM Roles for ECS Tasks (critical for container security)
  • Least-privilege principle
  • Service roles vs. instance roles
  • Avoid hard-coded AWS access keys in application code

3.2 AWS CLI — Command Line Interface
Purpose: Provides terminal-based control of AWS resources and is heavily used in automation and CI/CD.

  • Installation and configuration with aws configure
  • Credential management
  • Common S3, EC2, and ECS commands
  • Named profiles for dev/prod environments
  • Using environment variables and role-based credentials in automation

3.3 AWS EC2 — Elastic Compute Cloud
Purpose: Provides virtual machines. EC2 is especially useful for understanding the compute layer behind container platforms.

  • Instance types and sizing
  • Security Groups
  • Key pairs and SSH access
  • User Data scripts
  • Basic AMI and instance lifecycle concepts
  • Understand the underlying compute used by EKS worker nodes

3.4 AWS S3 — Simple Storage Service
Purpose: Object storage for documents, static assets, logs, backups, and other durable files.

  • Buckets and objects
  • Bucket policies and permissions
  • Versioning
  • Static website hosting concepts
  • Lifecycle policies
  • Use case: agent documents, static assets, and backups

3.5 AWS RDS — Relational Database Service
Purpose: Managed relational databases such as PostgreSQL and MySQL. Useful when an agent application needs structured, transactional data.

  • Managed PostgreSQL/MySQL
  • Instance classes and storage
  • Security Groups and DB subnet groups
  • Automated backups
  • Read replicas
  • Use case: agent conversation history and structured application data

3.6 AWS CloudFormation — Infrastructure as Code
Purpose: Defines AWS infrastructure using declarative templates so environments can be created consistently and repeatably.

  • YAML/JSON templates
  • Stacks and change sets
  • Parameters and mappings
  • Resources and outputs
  • Use case: automate VPC, ECS, RDS, and related infrastructure

3.7 AWS Route 53 — DNS Service
Purpose: Routes domain names to AWS resources and supports DNS-based traffic management.

  • Hosted zones
  • A, CNAME, and Alias records
  • Routing policies: simple, weighted, and latency
  • Domain registration concepts
  • Use case: custom domains for agent APIs

3.8 AWS VPC — Virtual Private Cloud
Purpose: Creates an isolated network environment for AWS resources and is critical for production network security.

  • CIDR blocks and IP addressing
  • Public vs. private subnets
  • Route tables and Internet Gateway
  • NAT Gateway for private subnets
  • Security Groups vs. Network ACLs
  • VPC Peering basics
  • Critical goal: network isolation for production workloads

3.9 AWS ECS — Elastic Container Service
Purpose: Primary deployment target for this learning path. ECS runs containers without requiring you to operate a Kubernetes control plane.

  • Task Definitions using JSON/YAML-style configuration
  • Fargate vs. EC2 launch types
  • ECS Services and task scheduling
  • Application Load Balancer integration
  • Service Auto Scaling
  • IAM roles for ECS tasks
  • Use case: production Docker containers with managed infrastructure

3.10 AWS EKS — Elastic Kubernetes Service
Purpose: Managed Kubernetes on AWS. Use this after becoming comfortable with Docker, Kubernetes fundamentals, VPC, IAM, and ECS.

  • Managed Kubernetes control plane
  • Managed and unmanaged node groups
  • IAM Roles for Service Accounts (IRSA)
  • AWS Load Balancer Controller
  • Persistent storage with EBS/EFS
  • Use case: complex production agent orchestration and Kubernetes workloads

Terraform

4.1 Terraform Basics
Why learn it? Terraform is a popular Infrastructure as Code tool and a strong alternative/complement to CloudFormation, especially when infrastructure spans multiple providers.

  • HCL (HashiCorp Configuration Language)
  • Providers and resources
  • State management
  • terraform plan and terraform apply workflow
  • Variables, outputs, and modules
  • Use case: multi-cloud or reusable infrastructure automation

4.2 SSL/TLS Certificates
Why learn it? TLS encrypts traffic between clients and your application and enables HTTPS for production APIs and web applications.

  • Certificate Authority (CA) concept
  • Certificate Signing Requests (CSR)
  • Let's Encrypt integration
  • HTTPS enforcement and HTTP-to-HTTPS redirection
  • Certificate renewal
  • Use case: secure HTTPS endpoints for production agents and applications

Projects

6. Practical Project Progression:

Project 1 — Dockerize an Application: Containerize a simple backend and frontend; use environment variables, volumes, health checks, and Docker Compose.

Project 2 — Kubernetes Deployment: Deploy the same application with Pods/Deployments, Services, ConfigMaps, Secrets, resource limits, and rolling updates.

Project 3 — CI/CD: Create a GitHub Actions pipeline that tests the code, builds the Docker image, pushes it to a registry, and deploys it.

Project 4 — AWS ECS Production Deployment: Deploy the container to ECS/Fargate inside a VPC, expose it through an ALB, secure it with IAM and HTTPS, and connect it to RDS/S3.

Project 5 — AWS EKS: Deploy a Kubernetes version on EKS with managed node groups, AWS Load Balancer Controller, IAM integration, and persistent storage.
